
B3 - PERFORMANCE BENCHMARKING AND ANALYSIS

1. OBJECTIVE

The objective is to compare runtime polymorphism, switch-based
dispatch, exception handling, and std::variant using performance
measurements.

2. VIRTUAL FUNCTION VS SWITCH

The two approaches were tested with:
- 1,000 bills
- 1,000,000 bills
- 10,000,000 bills

Both approaches calculate the same billing totals.

Virtual functions provide extensibility because new bill types
can be added using derived classes.

Switch statements provide direct type-based selection but require
modifying the switch whenever a new bill type is introduced.

3. RETURN CODES VS EXCEPTIONS

One million claims were tested with:
- 0% invalid claims
- 1% invalid claims
- 50% invalid claims

Return codes explicitly indicate failure through a status value.
Exceptions transfer control to a catch block when an error occurs.

Return codes are generally suitable for frequently occurring
validation failures. Exceptions are useful for exceptional
situations because they separate error-handling logic from
normal processing.

4. STD::VARIANT AND STD::VISIT

std::variant stores one value from a fixed set of alternative
types. std::visit performs type-specific operations.

The variant implementation was compared with virtual functions
and switch-based dispatch using 10 million bills.

The size of VariantBill was measured using sizeof().

std::variant provides type safety but requires the possible
alternative types to be known at compile time.

6. CONCLUSION

The benchmark demonstrates that different dispatch and error
handling techniques have different performance and design
trade-offs.

Virtual functions support extensible object-oriented design.
Switch statements offer simple dispatch for a fixed set of types.
std::variant provides type-safe alternatives when the set of
types is known in advance.

Return codes are useful for frequent validation failures,
while exceptions are suitable for exceptional error conditions.

The final implementation choice should consider performance,
maintainability, extensibility, and application requirements.
